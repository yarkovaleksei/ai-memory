# Выпуск ai-memory

Прочитай `AGENTS.md`, `plan/decisions.md` (ADR-027 — ADR-030), `Taskfile.yml` (задачи `release*`), `.github/workflows/release.yml`. Сборку и проверки пакетов Linux выполняй по соседнему [ai-memory-build](../ai-memory-build/SKILL.md). Механику выполняют `wails3 task`, `git` и `gh`, отдельного скрипта выпуска нет.

Рецепт адаптирован по навыкам [forktopus-release](https://github.com/forktopus/forktopus/blob/main/.agents/skills/forktopus-release/SKILL.md) и songframe-release: проекты того же владельца на Wails v3.

Канал выпуска один — публичный `yarkovaleksei/ai-memory`. Опубликованные выпуски и их теги не удаляются и не переносятся: опубликованный выпуск исправляет только следующая версия.

## Объём поручения

- Просьба спланировать выпуск или написать описание разрешает только чтение, анализ diff, ревизию документации, план версии и черновик описания.
- Commit, push, тег, создание черновика, загрузка файлов и публикация — только по явному поручению. Поручение на один шаг не распространяется на следующие. Явное поручение «выпусти версию X.Y.Z» разрешает все шаги до публикации включительно; повторно не спрашивай.
- Прямой запрет на коммиты, теги или публикацию важнее.
- Разработка этого навыка не является поручением выпустить версию.

## Состав выпуска

Имена файлов и примечания — как в таблице «Установка» README:

- `ai-memory_<версия>_amd64.deb`, `ai-memory-<версия>.x86_64.rpm`, `ai-memory-<версия>-x86_64.pkg.tar.zst`, `SHA256SUMS-linux.txt` — собирает и выкладывает владелец локально;
- `ai-memory-<версия>-macos-universal.dmg`, `SHA256SUMS-macos.txt` — CI, без нотаризации, подпись ad-hoc;
- `ai-memory-<версия>-windows-amd64-setup.exe`, `SHA256SUMS-windows.txt` — CI, без подписи, SmartScreen предупредит.

MCP-мост входит в каждый пакет: `/usr/bin/ai-memory-mcp`, `/Applications/ai-memory.app/Contents/MacOS/ai-memory-mcp`, `%LOCALAPPDATA%\Programs\ai-memory\ai-memory-mcp.exe`.

Пакеты macOS и Windows ни на одной настоящей машине не запускались, пока это не подтвердит пользователь с такой системой. В описании выпуска так и пиши.

## Порядок выпуска

### 1. Предусловия

- Дерево чистое, HEAD совпадает с `origin/main`. Незакоммиченное в выпуск не входит; другой SHA молча не собирай.
- Проверка `check` в CI на этом SHA зелёная на трёх системах: `gh run list --workflow check --branch main --limit 3`. Красную проверку не обходи: назови упавшую систему и разбери лог (длинные логи — субагенту log-reader).
- Локально один раз `wails3 task check`.

### 2. Ревизия документации

- Возьми diff от тега предыдущего выпуска (`git diff --stat v<прежняя>..HEAD`; для первого выпуска — вся история).
- Сверь с кодом по существу: строку «Статус» и разделы «Установка» и «MCP-мост» в `README.md` и `README.en.md` (они синхронны), команды в `AGENTS.md`, статусы фаз в `plan/`. Для каждого затронутого документа можно поручить субагенту без наследования чата сверить его утверждения с кодом: он получает документ, список изменённых файлов и правило сообщать расхождения с цитатой и местом в коде, ничего не меняя.
- Правки документации входят в выпуск отдельным коммитом, только если commit входит в поручение. В итоге перечисли проверенные документы и найденные расхождения; «расхождений нет» — тоже результат.

### 3. Версия и описание

- SemVer по существенному diff, а не по сообщениям коммитов (`gh release list` — прежние выпуски): patch — исправления, minor — возможности, major — несовместимые изменения настроек, индекса или бэкапов без миграции. Пока проект в `0.x`, несовместимое поднимает minor.
- Версия живёт только в теге: файла версии нет (ADR-027).
- Описание — по-русски в `bin/release/notes-<версия>.md` (каталог не в git): полезные пользователю изменения, действия при обновлении, известные ограничения. Пустых разделов нет. Внутреннюю историю разработки, приватные пути и ни байта реальной памяти не переноси (AGENTS.md).
- Таблицу установки давай прямыми ссылками `https://github.com/yarkovaleksei/ai-memory/releases/download/v<версия>/<имя-файла>`. Не обещай подпись, отсутствие предупреждений Gatekeeper и SmartScreen или проверку на macOS и Windows.

### 4. Тег

Аннотированный тег на проверенный SHA: `git tag -a v<версия> -m "ai-memory <версия>"`, затем `git push origin v<версия>`. Тег запускает `release.yml`: CI собирает macOS и Windows и создаёт черновик релиза, если его ещё нет. Тег после push не переносится.

### 5. Пакеты Linux

`wails3 task release` на теге, затем проверки по ai-memory-build. Установку и `smoke:desktop` на установленном пакете проводит владелец или агент по его поручению: то, что выкладывается для Linux, должно быть поставлено и открыто из меню на этой машине.

### 6. Черновик

`wails3 task release:publish NOTES=bin/release/notes-<версия>.md` создаёт черновик (если CI не успел), ставит описание и загружает пакеты Linux без `--clobber`. Черновик не виден как `releases/latest`, на нём безопасно проверять вложения.

### 7. CI

Дождись `release.yml` на теге: `gh run list --workflow release --limit 1`, затем `gh run watch <id>` в фоне. При сбое назови упавшую систему и причину. Перезапуск `gh run rerun <id> --failed` — по поручению. Пакеты macOS и Windows локально вместо CI не собирай.

### 8. Сверка вложений

`wails3 task release:verify`: все восемь файлов `ok`, лишних нет. Сверка идёт только по метаданным API — `digest`, `state`, `size`. Пакеты Linux сверяются с локальными файлами, пакеты macOS и Windows — с их `SHA256SUMS-<система>.txt`. Сами пакеты обратно не скачивай. Отсутствующий или несовпадающий digest — непроверенный результат: разбирайся, не публикуй.

### 9. Публикация

Только по поручению выпустить эту версию: `wails3 task release:promote`. Задача сверяет вложения, публикует черновик как latest и сверяет ещё раз. Убедись, что `gh release view --json isDraft,tagName` показывает опубликованный выпуск, и только после этого давай ссылку.

При сбое сначала выясни фактическое состояние тега, черновика и вложений, затем повтори только недостающий шаг. Релиз и тег не удаляй, `--clobber` не применяй, под опубликованным номером не пересобирай. Лишний или битый файл в черновике удаляется `gh release delete-asset` только по поручению.

## Что сообщить

Раздельно:

- план и выбранную версию;
- исходный SHA и состояние дерева, результат `check` в CI и локально;
- ревизию документации;
- собранные пакеты Linux и выполненные проверки;
- состояние тега, черновика или опубликованного выпуска и итог `release:verify`;
- незакрытые условия, в том числе непроверенные macOS и Windows.
