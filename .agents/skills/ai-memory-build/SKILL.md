# Сборка ai-memory

Работай в корне репозитория. Перед сборкой прочитай `AGENTS.md`: раздел «Команды» и правила безопасности реальной памяти. Решения о пакетах — ADR-027, ADR-028 и ADR-029 в `plan/decisions.md`. Если эта памятка расходится с ними или с `Taskfile.yml`, верны они.

Рецепт адаптирован по навыкам [forktopus-release](https://github.com/forktopus/forktopus/blob/main/.agents/skills/forktopus-release/SKILL.md) и songframe-build: проекты того же владельца на Wails v3.

## Объём поручения

- Сборка не разрешает commit, push, тег, публикацию и установку пакета. `sudo apt install` выполняет владелец сам.
- Изменение рецепта не разрешает пересборку или запуск артефакта без поручения. Проверяй изменённую область адресно, полную матрицу по своей инициативе не запускай.
- Логи и временные файлы — в scratchpad или `/tmp`, не в репозитории. Сборки длинные: запускай их в фоне и не опрашивай без нужды.

## Что собирается где

| Система | Где | Пакеты |
|---|---|---|
| Linux amd64 | локально, `wails3 task package` или `wails3 task release` | deb, rpm, пакет Arch; окно и мост в `/usr/bin` |
| Windows amd64 | CI по тегу | установщик NSIS для текущего пользователя |
| macOS, universal | CI по тегу | `.dmg` с `.app`, подпись ad-hoc |

Установщик Windows кросс-собирается и на Linux (`wails3 task windows:package`, нужен `makensis`). Это проверка состава установщика, а не запуск в Windows. Без поручения его не собирай: релизную версию собирает CI. Пакет macOS с Linux не собирается вовсе (ADR-029).

## Сборка

- Версию покажет `wails3 task version`. Без тега это `0.0.1-dev`, в пакетах — числовая часть `0.0.1`. Не выдавай пакет с незакоммиченными изменениями за чистый снимок HEAD: суффикс `-dirty` в версии об этом и говорит.
- Обычная сборка пакетов текущей системы: `wails3 task package`, результат в `bin/` (`ai-memory.deb`, `ai-memory.rpm`, `ai-memory.pkg.tar.zst`, `ai-memory`, `ai-memory-mcp`).
- Сборка для релиза: `wails3 task release`. Работает только с чистого тега `vX.Y.Z` на HEAD и кладёт файлы с версией в имени и `SHA256SUMS-linux.txt` в `bin/release/<версия>/`. Пробная сборка без тега: `wails3 task release APP_VERSION=X.Y.Z` — только для проверки рецепта, такие файлы не выкладываются.

## Проверки

Все проверки — на свежей копии `fixtures/home` в `.task/`, не на реальной памяти.

1. **Состав deb.** `dpkg-deb -I` — версия и зависимости `libgtk-4-1`, `libwebkitgtk-6.0-4`. `dpkg-deb -c` — `/usr/bin/ai-memory`, `/usr/bin/ai-memory-mcp`, `/etc/apparmor.d/ai-memory` с правами `0644`, ярлык и иконка. У rpm и пакета Arch состав проверяй через `rpm -qpl` и `bsdtar -tf`, если они есть; иначе так и скажи, что не проверено.
2. **MCP-мост:** `wails3 task smoke:mcp` (или `BIN=/usr/bin/ai-memory-mcp` для установленного). Мост по stdio находит в копии фикстур факт Claude и не создаёт ни каталога данных, ни каталога настроек.
3. **Окно как из меню:** `wails3 task smoke:desktop` после того, как владелец поставил пакет. Окно запускается через пользовательский systemd на 8 секунд и появляется на экране — предупреди владельца. Успех — «проработал 8 с».

Запуск окна из оболочки агента ничего не доказывает. Claude Code и Codex передают дочерним процессам свой профиль AppArmor с правом на user namespaces, и окно открывается даже там, где из меню падает (ADR-028). Поэтому только `smoke:desktop`.

Песочница WebKit остаётся включённой. Не ставь `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS`, не выключай AppArmor и не меняй `kernel.apparmor_restrict_unprivileged_userns` ради успешной проверки. Если `smoke:desktop` падает с SIGTRAP и в журнале ядра есть `apparmor="DENIED" … comm="bwrap"`, не загружен профиль `/etc/apparmor.d/ai-memory`.

## Что сообщить

Путь к собранным файлам и версию, результат каждой выполненной проверки, а невыполненные — с причиной. Отдельно укажи, что Linux-результат не переносится на macOS и Windows, и что пакеты не ставились, если их не ставил владелец.
