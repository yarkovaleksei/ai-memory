# Инструкции для агентов

Этот файл читают Codex (напрямую) и Claude Code (через импорт в `CLAUDE.md`). Правила общие для обоих агентов. Специфичное для одного агента — в его файле.

## Проект

ai-memory — десктоп-приложение (Go + Wails v3, react-admin) для памяти Claude Code и Codex. Обзор — [README.md](README.md), устройство — [plan/architecture.md](plan/architecture.md).

## Работа по плану

План в [plan/](plan/README.md) — источник правды.

- Перед задачей найди её в текущей фазе в `plan/phases/`. Задачи нет — сначала допиши её в фазу, потом делай.
- Не начинай следующую фазу, пока не выполнены критерии готовности текущей. Исследовательские задачи из `plan/open-questions.md` можно брать в любой момент.
- Выполненные задачи отмечай `- [x]` в том же коммите, что и код. Статус фазы меняй в `plan/README.md` и в файле фазы.
- Архитектурное решение — новая запись в `plan/decisions.md`. Принятые записи не переписывай: добавь новую, а у старой поставь «заменено ADR-NNN».
- Решения со статусом «предложено» не считай принятыми: если задача от них зависит, спроси владельца.
- Новый факт о формате памяти или опровержение старого — правка `plan/storage-formats.md` с пометкой, что и когда проверено.

## Безопасность реальной памяти

Это главное правило проекта: код и агенты работают рядом с настоящей памятью владельца.

- **Тесты, разработка и эксперименты — только на `fixtures/`.** Корни памяти задаются переменными окружения; в тестах они всегда указывают на фикстуры.
- **Не пиши в `~/.claude*`, `~/.codex` и их подкаталоги** ни кодом, ни командами — ни в ходе тестов, ни «для проверки». Единственное исключение — ручная приёмка фазы 2 и дальше, и только с явного согласия владельца в чате.
- **Читать реальную память можно только для исследования форматов** (задачи из `plan/open-questions.md`), и только на чтение. SQLite открывай с `mode=ro`.
- **Никогда не читай** `~/.codex/auth.json`, `~/.claude*/.credentials.json`, файлы сессий целиком (`sessions/`, `thread_history_*.sqlite`, `logs_*.sqlite`). Для восстановления пути проекта из jsonl читай только поле `cwd`.
- **Ни байта реальной памяти в репозиторий:** ни в фикстуры, ни в тесты, ни в документацию, ни в сообщения коммитов. Примеры в документации — выдуманные.
- В Codex пишем только ad-hoc-заметками. Сгенерированные файлы (`memory_summary.md`, `MEMORY.md`, `raw_memories.md`, `rollout_summaries/`) — только чтение. Файлы заметок не удаляются никогда ([ADR-002](plan/decisions.md#adr-002-в-память-codex-писать-только-ad-hoc-заметками)).
- Любая запись в память агентов в коде идёт через `internal/writer` (план → diff → снимок → атомарная запись → коммит бэкапа). Прямых `os.WriteFile` и `os.Remove` по путям памяти в обход writer'а быть не должно.
- Интерфейс передаёт в Go только идентификаторы записей и планов, а не пути. Каждый путь проверяется на принадлежность разрешённым корням.
- `wails3 dev` по умолчанию запускай на фикстурах. На реальной памяти — только для приёмки и только на чтение до фазы 2.

## Язык

- Документация, комментарии в коде, сообщения коммитов и описания PR — на русском.

## Код

Стек — [ADR-006](plan/decisions.md#adr-006-стек-go--wails-v3-react-admin-yarn-4). Новую зависимость сверх него добавляй, только записав причину в `plan/decisions.md`.

### Go
- Ядро (`internal/`, кроме `internal/app`) не импортирует Wails, `internal/app` и ничего не знает о фронтенде. Wails-специфичный код — только в `main.go` и `internal/app`.
- `cmd/ai-memory-mcp` зависит только от ядра, не от Wails.
- Ошибки оборачивай с контекстом (`fmt.Errorf("…: %w", err)`), не теряй исходную.
- Всё, что ходит в файловую систему или запускает процессы, принимает `context.Context`.
- Парсеры форматов памяти терпимы: неизвестное поле сохраняется и не роняет разбор, неожиданная структура — запись в `Warnings`, а не ошибка.
- Frontmatter читай и пиши через `yaml.Node`, чтобы не терять порядок ключей и неизвестные поля.
- Каждое изменение адаптера или writer'а — с табличным тестом на фикстурах.

### Фронтенд
- Только yarn 4, `npm` и `npx` не используй. `yarn.lock` коммитится.
- TypeScript в режиме `strict`, `any` — только с комментарием-обоснованием.
- Вызовы Go — только через сгенерированные привязки Wails, обёрнутые в `dataProvider` или хуки. Сгенерированные файлы руками не правь — перегенерируй.

## Команды

Каркаса пока нет, точные команды появятся в фазе 0. Планируемые:

```bash
wails3 dev               # окно в режиме разработки с горячей перезагрузкой
wails3 task check        # все проверки: тесты, линт, типы
wails3 task test         # go test ./... и Vitest
wails3 task lint         # gofmt, go vet, staticcheck, ESLint, Prettier
wails3 task build        # сборка бинаря
```

Перед коммитом должна проходить `wails3 task check`.
