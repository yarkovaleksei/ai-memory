# Инструкции для агентов

Этот файл читают Codex (напрямую) и Claude Code (через импорт в `CLAUDE.md`). Правила общие для обоих агентов. Специфичное для одного агента — в его файле.

## Проект

ai-memory — десктоп-приложение (Go + Wails v3, react-admin) для памяти Claude Code и Codex. Обзор — [README.md](README.md), устройство — [plan/architecture.md](plan/architecture.md).

## Работа по плану

План в [plan/](plan/README.md) — источник правды.

- Перед задачей найди её в текущей фазе в `plan/phases/`. Задачи нет — сначала допиши её в фазу, потом делай.
- Не начинай следующую фазу, пока не выполнены критерии готовности текущей. Исследовательские задачи из `plan/open-questions.md` можно брать в любой момент.
- Выполненные задачи отмечай `- [x]` в том же коммите, что и код. Статус фазы меняй в `plan/README.md` и в файле фазы.
- Архитектурное решение — новая запись в `plan/decisions.md`. Принятые записи не переписывай: добавь новую, а у старой поставь «заменено ADR-NNN».
- Решения со статусом «предложено» не считай принятыми: если задача от них зависит, спроси владельца.
- Новый факт о формате памяти или опровержение старого — правка `plan/storage-formats.md` с пометкой, что и когда проверено.

## Безопасность реальной памяти

Это главное правило проекта: код и агенты работают рядом с настоящей памятью владельца.

- **Тесты, разработка и эксперименты — только на `fixtures/`.** Корни памяти задаются переменными окружения; в тестах они всегда указывают на фикстуры.
- **Не пиши в `~/.claude*`, `~/.codex` и их подкаталоги** ни кодом, ни командами — ни в ходе тестов, ни «для проверки». Единственное исключение — ручная приёмка фазы 2 и дальше, и только с явного согласия владельца в чате.
- **Читать реальную память, инструкции и навыки агентов можно только для исследования форматов** (задачи из `plan/open-questions.md` и исследовательские задачи фаз), и только на чтение. SQLite открывай с `mode=ro`.
- Проектные `CLAUDE.md` и `AGENTS.md` лежат в чужих git-репозиториях: ai-memory никогда не коммитит в них и не трогает их git-состояние.
- Навык-симлинк правится только с явным предупреждением, что изменение затронет всех, кто на него ссылается.
- **Никогда не читай** `~/.codex/auth.json`, `~/.claude*/.credentials.json`, файлы сессий целиком (`sessions/`, `thread_history_*.sqlite`, `logs_*.sqlite`). Для восстановления пути проекта из jsonl читай только поле `cwd`.
- **Ни байта реальной памяти в репозиторий:** ни в фикстуры, ни в тесты, ни в документацию, ни в сообщения коммитов. Примеры в документации — выдуманные.
- В Codex пишем только ad-hoc-заметками. Сгенерированные файлы (`memory_summary.md`, `MEMORY.md`, `raw_memories.md`, `rollout_summaries/`) — только чтение. Файлы заметок не удаляются никогда ([ADR-002](plan/decisions.md#adr-002-в-память-codex-писать-только-ad-hoc-заметками)).
- Любая запись в память агентов в коде идёт через `internal/writer` (план → diff → снимок → атомарная запись → коммит бэкапа). Прямых `os.WriteFile` и `os.Remove` по путям памяти в обход writer'а быть не должно.
- Интерфейс передаёт в Go только идентификаторы записей и планов, а не пути. Каждый путь проверяется на принадлежность разрешённым корням.
- `wails3 dev` по умолчанию запускай на фикстурах. На реальной памяти — только для приёмки и только на чтение до фазы 2.

## Язык

- Документация, комментарии в коде, сообщения коммитов и описания PR — на русском.
- Идентификаторы, публичные API, имена файлов и устоявшиеся термины — на английском.
- Комментарий объясняет, зачем код и какой инвариант он держит, а не пересказывает строку.
- `README.md` — основной, `README.en.md` — его перевод для внешних читателей. Меняешь один — приведи в соответствие второй в том же коммите.
- Проект открытый ([ADR-007](plan/decisions.md#adr-007-открытый-проект-под-лицензией-mit)): в коде, документации и фикстурах — никаких путей, имён проектов и данных с машины владельца. Примеры — выдуманные (`/home/me/projects/demo`).

## Код

Стек — [ADR-006](plan/decisions.md#adr-006-стек-go--wails-v3-react-admin-yarn-4). Новую зависимость сверх него добавляй, только записав причину в `plan/decisions.md`.

### Go
- Ядро (`internal/`, кроме `internal/app`) не импортирует Wails, `internal/app` и ничего не знает о фронтенде. Wails-специфичный код — только в `main.go` и `internal/app`.
- `cmd/ai-memory-mcp` зависит только от ядра, не от Wails.
- Ошибки оборачивай с контекстом (`fmt.Errorf("…: %w", err)`), не теряй исходную.
- Всё, что ходит в файловую систему или запускает процессы, принимает `context.Context`.
- Код переносим на Linux, macOS и Windows ([ADR-009](plan/decisions.md#adr-009-linux-macos-и-windows-с-самого-начала)): пути — только через `filepath` и `os.UserHomeDir`/`os.UserConfigDir`, каталоги ai-memory — только через `internal/config`, системно-зависимый код — в файлах с build-тегами. Проверено только на Linux — так и пиши в отчёте.
- Парсеры форматов памяти терпимы: неизвестное поле сохраняется и не роняет разбор, неожиданная структура — запись в `Warnings`, а не ошибка.
- Frontmatter читай и пиши через `yaml.Node`, чтобы не терять порядок ключей и неизвестные поля.
- Каждое изменение адаптера или writer'а — с табличным тестом на фикстурах.

### Фронтенд
- Только yarn 4, `npm` и `npx` не используй. `yarn.lock` коммитится.
- TypeScript в режиме `strict`, `any` — только с комментарием-обоснованием.
- Вызовы Go — только через сгенерированные привязки Wails, обёрнутые в `dataProvider` или хуки. Сгенерированные файлы руками не правь — перегенерируй.
- Ни одной строки интерфейса прямо в JSX: всё через `useTranslate` и ключи в словаре ([ADR-008](plan/decisions.md#adr-008-интерфейс-на-русском-через-i18n-с-первого-дня)). Новый ключ добавляется в словарь в том же коммите.
- Ошибки из Go приходят кодом с параметрами, текст для человека собирает фронтенд по словарю.

## Команды

Все задачи — в `Taskfile.yml`, запуск через `wails3 task <имя>` из корня репозитория. Нужны Go 1.26, Node 24 с corepack (yarn 4.18.1 подтянется сам) и `wails3` v3.0.0 (`go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0`); на Linux — GTK 4 и WebKitGTK 6.0 (`wails3 doctor` покажет, чего не хватает).

```bash
wails3 task dev          # окно в режиме разработки на свежей копии фикстур (.task/dev-home)
wails3 task dev REAL=true  # то же на настоящей памяти — только для приёмки
wails3 task check        # всё перед коммитом: yarn install --immutable, тесты, типы, линтеры
wails3 task test         # go test ./internal/... и Vitest
wails3 task lint         # gofmt, go vet, staticcheck, ESLint, Prettier
wails3 task typecheck    # tsc --noEmit
wails3 task fmt          # отформатировать Go и фронтенд
wails3 task bindings     # перегенерировать frontend/bindings после изменения сервисов в internal/app
wails3 task build        # собрать бинарь в bin/
wails3 task build:mcp    # собрать MCP-мост bin/ai-memory-mcp (без Wails и фронтенда)
wails3 task package      # пакеты текущей ОС с окном и мостом в bin/; версия — из тега vX.Y.Z (wails3 task version)
wails3 task release      # пакеты Linux для релиза в bin/release/<версия>/, только с чистого тега vX.Y.Z
wails3 task release:publish  # приложить их к черновику релиза GitHub через gh (только по просьбе владельца)
wails3 task release:verify   # сверить вложения релиза по digest из API GitHub
wails3 task release:promote  # опубликовать черновик после сверки (только по просьбе владельца)
wails3 task smoke:mcp        # собранный MCP-мост по stdio на копии фикстур
wails3 task smoke:desktop    # окно как из меню, через пользовательский systemd (после установки пакета)
wails3 task mcp:dev      # то же плюс команды, которые подключают мост к Claude Code и Codex на копии фикстур
```

- Перед коммитом должна проходить `wails3 task check`.
- `lint` сначала собирает фронтенд: пакету `main` для `go vet` нужен `frontend/dist` (`//go:embed`).
- Сайт — `www/index.html` без сборки, публикуется `.github/workflows/pages.yml` по push в `main` ([ADR-032](plan/decisions.md#adr-032-сайт--статическая-страница-в-www-на-github-pages)). Перед push смотри его в браузере: `python3 -m http.server 8765 --directory www` (для Claude Code — конфигурация `site` в `.claude/launch.json`). Скриншоты — только с окна на `fixtures/`, без путей с машины разработчика.
- Сборка пакетов и выпуск версии — по навыкам `ai-memory-build` и `ai-memory-release` в `.agents/skills/` (для Claude Code — симлинки в `.claude/skills/`, [ADR-030](plan/decisions.md#adr-030-релиз-выкладывается-черновиком-и-публикуется-после-сверки-по-api)).
- Пакеты: установщик Windows собирается и на Linux, нужен `makensis` (NSIS); универсальный `.app` и `.dmg` — только на macOS. Пакеты macOS и Windows для релиза собирает CI по тегу `vX.Y.Z`, Linux — владелец локально ([ADR-027](plan/decisions.md#adr-027-упаковка-без-подписи-deb-rpm-arch-dmg-и-nsis-с-mcp-мостом), [ADR-029](plan/decisions.md#adr-029-linux-собирается-локально-macos-и-windows--в-ci)).
- `frontend/bindings` коммитится. Поменял сервис в `internal/app` — перегенерируй привязки в том же коммите; CI проверяет, что они совпадают с Go-кодом.
- TypeScript закреплён на 6.0: `typescript-eslint` пока не поддерживает 7.x. Обновлять вместе.
- `Route` и прочее из роутера импортируй из `react-router-dom`, как сам react-admin: иначе в тестах получаются два экземпляра роутера.
- yarn не ставит версии моложе 7 дней (`npmMinimalAgeGate` в `frontend/.yarnrc.yml`).

## Git

- Работа идёт прямо в `main`, без веток и PR.
- Коммитить и пушить — только по просьбе владельца.
- Один коммит — одно логическое изменение вместе с отметками в плане. Заголовок коммита — повелительное наклонение на русском («Добавить адаптер Claude»), в теле — зачем и что изменилось.
