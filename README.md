# ai-memory

[English version](README.en.md)

Десктоп-приложение для памяти Claude Code и Codex: просмотр по проектам, поиск, редактирование, удаление, перенос фактов между агентами и объединение дублей.

> **Статус:** фазы 1 (просмотр), 2 (редактирование), 3 (между агентами), 4 (инструкции и навыки) и 5 (MCP-мост) готовы. Фаза 6, упаковка, в работе: пакеты для трёх систем собираются, проверены пока только на Linux. Окно показывает память Claude Code и Codex по проектам, с поиском; факты Claude правятся, создаются и удаляются, в Codex пишутся заметки. Записи переносятся между агентами, отмеченные в списке объединяются и проверяются на противоречия, в том числе с черновиком от модели. Рядом с памятью видны инструкции (`CLAUDE.md`, `AGENTS.md`, правила) и навыки: правило переносится между `CLAUDE.md` и `AGENTS.md` разделом, навык ставится в другого агента копией или симлинком. Через MCP-мост `ai-memory-mcp` агент во время работы ищет в памяти другого агента. Каждая запись проходит через diff, бэкап и историю с откатом; для записи нужен `git`. Работа идёт по [плану](plan/README.md). Запуск и проверки — раздел «Команды» в [AGENTS.md](AGENTS.md).

## Зачем

Если чередовать Claude Code и Codex, у каждого копится своя память, а другой агент её не видит. Вывод, сделанный в одном агенте, приходится повторять в другом. Посмотреть, что агент о тебе «помнит», и навести там порядок, можно только руками в файлах в разных форматах.

Готовые инструменты (claude-mem, codemem, Basic Memory, mem0/OpenMemory) решают другую задачу: добавляют отдельный общий слой памяти через MCP. Родную автопамять агентов они не показывают и не правят.

## Как это устроено

ai-memory не заводит собственной памяти, а работает поверх родных файлов агентов:

| Агент | Где лежит память | Как ai-memory пишет |
|---|---|---|
| Claude Code | `~/.claude*/projects/<проект>/memory/*.md` и индекс `MEMORY.md` | напрямую: файл факта и строка в индексе |
| Codex | `~/.codex/memories_v2/` (сводка и rollout-сводки, их генерирует сам Codex) | только ad-hoc-заметками в `extensions/ad_hoc/notes/`, которые Codex вливает в память при консолидации |

Каждая запись проходит предпросмотр diff и сохраняется в собственный репозиторий бэкапов, поэтому любую операцию можно откатить.

Подробно: [форматы памяти](plan/storage-formats.md), [архитектура](plan/architecture.md), [решения](plan/decisions.md).

## Настройки

Без настроек ai-memory читает профиль Claude Code `~/.claude` (и каталог из `CLAUDE_CONFIG_DIR`, если переменная задана) и Codex из `~/.codex` (или `CODEX_HOME`). Если профилей Claude несколько, например рабочий и личный в разных каталогах, добавьте их на экране «Настройки»: каталог выбирается в системном диалоге, память перечитывается сразу. Экран пишет файл `config.toml` в каталоге настроек (на Linux `~/.config/ai-memory/`, на macOS `~/Library/Application Support/ai-memory/`, на Windows `%AppData%\ai-memory\`), его можно править и руками:

```toml
# Дополнительные профили Claude Code. Имена — любые, ~ раскрывается в домашний каталог.
extra_claude_profiles = ["~/.claude-work", "~/.claude-personal"]

# Корень Codex, если он не в ~/.codex и не задан через CODEX_HOME.
# codex_home = "/opt/codex"

# Поколение памяти Codex, в которое он сейчас пишет: "v1" (memories/) или "v2" (memories_v2/).
# Обычно не нужно: ai-memory определяет его сам по настройкам и базам Codex.
# codex_generation = "v2"

# Показывать и неактивное поколение (только чтение: Codex его уже не читает).
# show_codex_inactive = true
```

Каталог, указанный дважды, в том числе через симлинк, читается один раз. Настройки читаются при запуске, после правки перезапустите приложение.

## Установка

Пакеты лежат в [релизах GitHub](https://github.com/yarkovaleksei/ai-memory/releases), контрольные суммы — в `SHA256SUMS-<система>.txt`. MCP-мост `ai-memory-mcp` ставится вместе с окном. Пакеты не подписаны ([ADR-027](plan/decisions.md#adr-027-упаковка-без-подписи-deb-rpm-arch-dmg-и-nsis-с-mcp-мостом)), поэтому macOS и Windows при первом запуске попросят подтверждения. Как его дать, написано ниже.

| Система | Пакет | Окно | MCP-мост |
|---|---|---|---|
| Ubuntu 24.04+, Debian 13+ | `ai-memory_X.Y.Z_amd64.deb` | меню приложений, `ai-memory` | `/usr/bin/ai-memory-mcp` |
| Fedora 40+ | `ai-memory-X.Y.Z.x86_64.rpm` | меню приложений, `ai-memory` | `/usr/bin/ai-memory-mcp` |
| Arch Linux | `ai-memory-X.Y.Z-x86_64.pkg.tar.zst` | меню приложений, `ai-memory` | `/usr/bin/ai-memory-mcp` |
| macOS 12+, Apple Silicon и Intel | `ai-memory-X.Y.Z-macos-universal.dmg` | «Программы» → ai-memory | `/Applications/ai-memory.app/Contents/MacOS/ai-memory-mcp` |
| Windows 10 и 11, x64 | `ai-memory-X.Y.Z-windows-amd64-setup.exe` | меню «Пуск» и ярлык на рабочем столе | `%LOCALAPPDATA%\Programs\ai-memory\ai-memory-mcp.exe` |

**Linux.** Пакет ставится обычным менеджером пакетов и сам подтянет GTK 4 и WebKitGTK 6.0. В Ubuntu deb заодно ставит профиль AppArmor `/etc/apparmor.d/ai-memory`: без него песочница WebKit не запускается, и окно из меню не открывается ([ADR-028](plan/decisions.md#adr-028-deb-ставит-профиль-apparmor-с-правилом-userns)).

```bash
sudo apt install ./ai-memory_X.Y.Z_amd64.deb
```

```bash
sudo dnf install ./ai-memory-X.Y.Z.x86_64.rpm
```

```bash
sudo pacman -U ./ai-memory-X.Y.Z-x86_64.pkg.tar.zst
```

**macOS.** Откройте `.dmg` и перетащите ai-memory в «Программы». Приложение не нотаризовано, поэтому при первом запуске macOS скажет, что не может проверить разработчика. Есть два способа разрешить запуск:
- откройте «Системные настройки» → «Конфиденциальность и безопасность» и нажмите «Всё равно открыть» рядом с сообщением об ai-memory;
- или снимите карантин в терминале. Команда снимет его и с MCP-моста внутри приложения:

```bash
xattr -dr com.apple.quarantine /Applications/ai-memory.app
```

**Windows.** Запустите установщик. SmartScreen покажет «Система Windows защитила ваш компьютер»: нажмите «Подробнее», затем «Выполнить в любом случае». Установщик ставит ai-memory для текущего пользователя в `%LOCALAPPDATA%\Programs\ai-memory`, права администратора не нужны. Если в системе нет WebView2, установщик скачает его.

**Обновление** — установка нового пакета поверх старого. Индекс, бэкапы и настройки лежат в каталогах данных и настроек пользователя (см. «Данные и приватность»), и пакеты их не трогают. После удаления приложения эти каталоги тоже остаются: удалите их вручную, если они не нужны.

**Из исходников:** `wails3 task package` собирает пакеты текущей системы в `bin/`. Что для этого нужно — раздел «Команды» в [AGENTS.md](AGENTS.md). Пакеты Linux для релиза собираются локально, пакеты macOS и Windows — в GitHub Actions по тегу ([ADR-029](plan/decisions.md#adr-029-linux-собирается-локально-macos-и-windows--в-ci)).

Проверено только на Linux. Пакеты для macOS и Windows собираются в CI, но на этих системах ещё не запускались. Где там лежит память агентов, пока тоже не проверено ([Q10](plan/open-questions.md)).

## MCP-мост

`ai-memory-mcp` — отдельный бинарь без окна, Wails и GTK. Его запускает сам агент как MCP-сервер по stdio, и во время работы агент находит, что о проекте знает другой агент. Инструменты только читают:

| Инструмент | Что делает |
|---|---|
| `list_projects` | видимые проекты и текущий |
| `search_memory(query?, project?, agent?, kind?, limit?)` | короткая выдача: id, заголовок, описание, сниппет, вид записи (`memory`, `instructions`, `skill`). По умолчанию — записи другого агента по текущему проекту |
| `get_memory(id)` | запись целиком |

Мост ничего не пишет: ни в память агентов, ни в каталог данных ai-memory. Индекс он строит в памяти процесса и перечитывает файлы не чаще раза в 10 секунд. Корни памяти — те же, что у окна: переменные окружения и `config.toml`.

Мост ставится вместе с приложением, путь к нему для каждой системы — в таблице раздела «Установка». Из исходников его собирает `wails3 task build:mcp` в `bin/`. Подключить для всех проектов (пример — путь на Linux):

```bash
claude mcp add --scope user ai-memory -- /usr/bin/ai-memory-mcp -agent claude
```

В Codex — командой `codex mcp add ai-memory -- /usr/bin/ai-memory-mcp -agent codex` или разделом в `~/.codex/config.toml`:

```toml
[mcp_servers.ai-memory]
command = "/usr/bin/ai-memory-mcp"
args = ["-agent", "codex"]
```

Флаги сервера:

| Флаг | Что меняет |
|---|---|
| `-agent claude\|codex` | кто подключается: поиск по умолчанию идёт по памяти другого. Без флага угадывается по имени клиента |
| `-project <каталог>` | каталог проекта. По умолчанию — рабочий каталог, в котором агент запустил сервер |
| `-global` | видна и глобальная память: общие факты, глобальные `CLAUDE.md` и `AGENTS.md`, навыки пользователя |
| `-all-projects` | видны все проекты, а не только текущий; в поиске можно указать `project: "all"` |
| `-refresh 10s` | как часто перечитывать память |

Видимость задаётся только флагами: агент не может сам расширить её аргументами. Решение и его причины — [ADR-026](plan/decisions.md#adr-026-mcp-мост-свой-индекс-в-памяти-текущий-проект-память-другого-агента).

## Возможности по фазам

1. **Просмотр (MVP).** Память обоих агентов по проектам, фильтры, полнотекстовый поиск. Только чтение.
2. **Редактирование.** Создание, правка, удаление с diff, бэкапом и откатом.
3. **Между агентами.** Перенос фактов Claude ↔ Codex; объединение отмеченных записей и поиск противоречий среди них (черновик и проверка — с помощью LLM через `claude -p` / `codex exec`).
4. **Инструкции и навыки.** `CLAUDE.md`, `AGENTS.md` и навыки рядом с памятью, перенос правил и навыков между агентами.
5. **MCP-мост.** Агент во время работы ищет в памяти другого агента.
6. **Упаковка.** Установочные пакеты для Linux, macOS и Windows.

## Стек

- **Ядро и окно:** Go 1.26 и Wails v3. Интерфейс вызывает Go напрямую через привязки Wails, HTTP-сервера нет.
- **Интерфейс:** React, TypeScript, Vite, react-admin 5, MUI, CodeMirror 6. Пакеты — yarn 4. Язык интерфейса — русский, все строки через i18n с первого дня.
- **Индекс:** SQLite с полнотекстовым поиском FTS5.
- **Задачи:** `Taskfile.yml` через `wails3 task`.
- **Системы:** Linux, macOS и Windows.

Подробнее и почему — [ADR-006](plan/decisions.md#adr-006-стек-go--wails-v3-react-admin-yarn-4).

## Данные и приватность

- У приложения нет сетевого порта, память никуда не отправляется.
- Свои данные (индекс и бэкапы) ai-memory хранит в каталоге данных пользователя: на Linux `~/.local/share/ai-memory/`, на macOS `~/Library/Application Support/ai-memory/`, на Windows `%LocalAppData%\ai-memory\`. Их можно удалить: всё пересоберётся из родных файлов агентов.
- В репозиторий не попадает ни одного байта реальной памяти: тесты работают на фикстурах.
