# Открытые вопросы

У каждого вопроса — фаза, до которой его нужно закрыть, и способ проверки.

## Открытые

### Q8. Не порождают ли вызовы `claude -p` / `codex exec` для LLM-операций новую память?
- **Нужно к:** фазе 3.
- **Как проверить:** вызвать, затем посмотреть, появилась ли сессия в `stage1_outputs` или новый каталог проекта у Claude. Если да — искать флаг отключения или запускать с отдельным `CODEX_HOME`/`CLAUDE_CONFIG_DIR`.
- **Что уже известно (2026-11-10, по исходникам Codex 0.159.2 и 0.167.0-alpha.3.2):** `codex exec` запускает конвейер памяти, как и обычная сессия, кроме режима `--ephemeral`. Для Claude не проверено.

### Q10. Где лежит память агентов на macOS и Windows?
- **Нужно к:** фазе 1 (пути по умолчанию) и окончательно — к фазе 6.
- **Что известно (2026-11-10, по документации и сторонним источникам):** те же `.claude` и `.codex` в домашнем каталоге (`%USERPROFILE%` на Windows), имя каталога проекта Claude на Windows — вида `C--Users-me-…`. Подробнее — [storage-formats.md](storage-formats.md#macos-и-windows).
- **Чего не хватает:** проверки на живых macOS и Windows и прогона CI-матрицы.
- **Как проверить:** документация агентов; запуск тестов адаптеров в CI на macOS и Windows на фикстурах; ручная проверка на живой машине, когда она появится.

## Закрытые

### Q2. Когда Codex запускает консолидацию и подхватывает ad-hoc-заметки?
- **Ответ (2026-11-10, по исходникам Codex 0.159.2 и 0.167.0-alpha.3.2 и по базам на машине владельца):** консолидация (этап 2) запускается в начале хода с вводом пользователя в корневой сессии — в CLI, TUI, приложении и `codex exec` (кроме `--ephemeral`), — сразу после этапа 1. Не чаще раза в 6 часов после успешной консолидации; после ошибки — через час. Своего таймера, реакции на изменение файлов и ручного запуска нет: новая заметка будет учтена в первом ходе любой сессии Codex после окончания 6-часовой паузы. Изменения Codex находит через `git diff` каталога памяти с базовым коммитом «Initialize Codex git baseline»; после консолидации базовый коммит пересоздаётся, история не хранится.
- **Где учтено:** [storage-formats.md](storage-formats.md#конвейер-генерации), задачи «ожидает консолидации» и проверки перед записью в [фазе 2](phases/02-editing.md).

### Q3. Читает ли Codex ad-hoc-заметки из `memories/` (v1), если активно v2?
- **Ответ (2026-11-10, по исходникам):** нет. Каждое поколение читает заметки только из своего каталога. Какое поколение активно, решает настройка `[memories] version` в `config.toml` Codex и версия клиента: CLI 0.159 без настройки работает с v1, Codex 0.167 в приложении ChatGPT у владельца работает с v2. Поэтому ai-memory должен определять активное поколение, а не считать им v2.
- **Где учтено:** [storage-formats.md](storage-formats.md#два-поколения-памяти), задача определения поколения в [фазе 2](phases/02-editing.md).

### Q1. Какое поколение памяти Codex активно — v1 или v2?
- **Ответ (2026-11-10, проверено на Codex CLI 0.159.2):** v2. В нём прошла консолидация и Codex читает из него память; v1 заброшено с 2026-11-09, его консолидация висит в `pending`.
- **Где учтено:** [storage-formats.md](storage-formats.md#два-поколения-памяти) — по умолчанию v2, v1 только по настройке и только чтение.

### Q4. Есть ли `cwd` во всех файлах сессий Claude?
- **Ответ (2026-11-10, проверено):** да, везде, где есть `*.jsonl`, и закодированный `cwd` всегда совпадает с именем каталога. Но из 28 каталогов с памятью у 2 файлов сессий нет — для них нужен подбор по диску.
- **Где учтено:** [storage-formats.md](storage-formats.md#кодирование-пути-проекта), задача подбора пути в [фазе 1](phases/01-read-only.md).

### Q5. Нужно ли показывать память с других машин?
- **Ответ (2026-11-10, владелец):** нет, только локально. Один компьютер — одна установка.
- **Где учтено:** [фаза 6](phases/06-packaging.md) — задачи про удалённые источники убраны.

### Q6. Считать ли памятью `CLAUDE.md`, `AGENTS.md` и навыки?
- **Ответ (2026-11-10, владелец):** да, и инструкции, и навыки входят в охват.
- **Где учтено:** [ADR-010](decisions.md#adr-010-инструкции-и-навыки-агентов--тоже-в-охвате), отдельная [фаза 4](phases/04-instructions-skills.md).

### Q7. Что делать с памятью временных проектов (`-tmp-…`, scratchpad)?
- **Ответ (2026-11-10, владелец):** отдельная группа «Временные». По умолчанию свёрнута и не участвует в поиске, включается фильтром.
- **Где учтено:** [фаза 1](phases/01-read-only.md) — признак временного проекта и фильтр.

- **Где учтено:** [ADR-009](decisions.md#adr-009-linux-macos-и-windows-с-самого-начала), каталоги в [architecture.md](architecture.md#каталоги-ai-memory), задачи CI и `internal/config` в [фазе 0](phases/00-foundation.md), установщики в [фазе 6](phases/06-packaging.md).
