# Фаза 1. Просмотр (MVP)

**Статус:** не начата

**Цель.** Увидеть память обоих агентов в одном окне: по проектам, с поиском, без единой записи на диск. Это MVP: уже полезно и абсолютно безопасно.

## Задачи

### Ядро (`internal/`)
- [ ] Модель `Source`, `Project`, `MemoryItem` ([architecture.md](../architecture.md#модель-данных)).
- [ ] Настройки приложения в `config.toml` в [каталоге настроек](../architecture.md#каталоги-ai-memory): дополнительные профили Claude, корень Codex, показывать ли память Codex v1. По умолчанию — `~/.claude`, `CLAUDE_CONFIG_DIR`, `~/.codex` / `CODEX_HOME` ([ADR-007](../decisions.md#adr-007-открытый-проект-под-лицензией-mit)).
- [ ] Признак временного проекта: путь внутри системного каталога временных файлов (`os.TempDir()`, `/tmp`) или в scratchpad-каталогах сессий агентов. Такие проекты — в группе «Временные», по умолчанию свёрнуты и не участвуют в поиске (Q7).
- [ ] Адаптер Claude: обнаружение профилей, обход `projects/*/memory`, парсинг frontmatter с допуском вариантов, восстановление пути проекта, сверка с `MEMORY.md` (расхождения — в `Warnings`).
- [ ] Адаптер Codex: активное поколение (по Q1), разделы `memory_summary.md`, заголовки и тело `rollout_summaries`, ad-hoc-заметки. Привязка к проекту по `cwd`.
- [ ] Нормализация проектов: один `Project` на реальный путь, объединяющий источники обоих агентов; глобальная память — проект `global`.
- [ ] Индекс SQLite + FTS5, полная пересборка при запуске.
- [ ] Наблюдение за файлами через `fsnotify`: подписка на каждый каталог памяти и на новые каталоги, инкрементальное обновление индекса.
- [ ] Табличные тесты адаптеров на фикстурах, включая кривые файлы.

### Сервисы Wails (`internal/app`)
- [ ] `ProjectsService.List()`, `ItemsService.List(filter)` (проект, агент, тип, запрос, сортировка, страница), `ItemsService.Get(id)`, `SourcesService.List()`.
- [ ] DTO для фронтенда: frontmatter уже разобран, без `yaml.Node`; общее число записей для пагинации.
- [ ] Событие Wails «индекс обновлён» после каждого инкрементального обновления.
- [ ] Привязки TypeScript сгенерированы `wails3 generate bindings` и лежат в `frontend/`.

### Интерфейс (`frontend/`)
- [ ] react-admin со своим `dataProvider` поверх привязок (только `getList`, `getOne`, `getMany`).
- [ ] Подписка на событие «индекс обновлён»: перечитать текущий список.
- [ ] Раскладка: слева дерево проектов, в центре список записей с бейджами агента и типа, справа просмотр записи (отрендеренный Markdown и сырой текст).
- [ ] Фильтры: агент, тип, проект, «показать временные проекты» (выключен по умолчанию), «есть предупреждения».
- [ ] Все строки — через словарь `ru`, предупреждения из `Warnings` переводятся по коду.
- [ ] Полнотекстовый поиск с подсветкой.
- [ ] Ссылки внутри памяти кликабельны: `[[slug]]` у Claude, `rollout_summaries/…` у Codex.
- [ ] Светлая и тёмная тема.

## Готово, когда
- `wails3 dev` открывает окно, где на реальных данных владельца видна память обоих профилей Claude и Codex.
- Один и тот же проект, известный обоим агентам, показан одной строкой с обоими источниками.
- Поиск находит факт по началу слова из тела меньше чем за секунду на объёме машины владельца.
- Тестом доказано, что ни один код фазы не пишет за пределы каталога данных ai-memory (например, запуск на фикстурах в каталоге только для чтения).

## Риски
- Большие файлы v1 (`MEMORY.md` 586 КБ, `raw_memories.md` 1 МБ). Смягчение: v1 по умолчанию выключено; если включено — нарезка на разделы и ленивая загрузка тела.
