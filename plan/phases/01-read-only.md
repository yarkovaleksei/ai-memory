# Фаза 1. Просмотр (MVP)

**Статус:** готова (2026-11-10)

**Цель.** Увидеть память обоих агентов в одном окне: по проектам, с поиском, без единой записи на диск. Это MVP: уже полезно и абсолютно безопасно.

## Задачи

### Ядро (`internal/`)
- [x] Модель `Source`, `Project`, `MemoryItem` ([architecture.md](../architecture.md#модель-данных)).
- [x] Настройки приложения в `config.toml` в [каталоге настроек](../architecture.md#каталоги-ai-memory): дополнительные профили Claude, корень Codex, показывать ли память Codex v1. По умолчанию — `~/.claude`, `CLAUDE_CONFIG_DIR`, `~/.codex` / `CODEX_HOME` ([ADR-007](../decisions.md#adr-007-открытый-проект-под-лицензией-mit)).
- [x] Один каталог профиля Claude под двумя именами (симлинк и цель, повтор в `extra_claude_profiles`) читается один раз; остаётся имя, указанное первым.
- [x] Признак временного проекта: путь внутри системного каталога временных файлов (`os.TempDir()`, `/tmp`) или в scratchpad-каталогах сессий агентов. Такие проекты — в группе «Временные», по умолчанию свёрнуты и не участвуют в поиске (Q7).
- [x] Адаптер Claude: обнаружение профилей, обход `projects/*/memory`, парсинг frontmatter с допуском вариантов, сверка с `MEMORY.md` (расхождения — в `Warnings`). Учесть настройку `autoMemoryDirectory` в `settings.json` профиля, если она задана.
- [x] Восстановление пути проекта Claude: `cwd` из первых строк `*.jsonl`; без файлов сессий — подбор по диску по правилу кодирования ([storage-formats.md](../storage-formats.md#кодирование-пути-проекта)); не вышло — закодированное имя. Тест подбора строит дерево каталогов в `t.TempDir()`.
- [x] Адаптер Codex: активное поколение (по Q1), разделы `memory_summary.md`, заголовки и тело `rollout_summaries`, ad-hoc-заметки. Привязка к проекту по `cwd`.
- [x] Нормализация проектов: один `Project` на реальный путь, объединяющий источники обоих агентов; глобальная память — проект `global`.
- [x] Индекс SQLite + FTS5, полная пересборка при запуске. «ё» приводится к «е» и в тексте, и в запросе ([architecture.md](../architecture.md#индекс-и-поиск)).
- [x] Наблюдение за файлами через `fsnotify`: подписка на каждый каталог памяти и на новые каталоги, пересборка индекса после паузы 400 мс. Пересборка полная: на сотнях файлов это доли секунды и нет риска рассинхронизации, которым грозит инкрементальное обновление (`internal/library`).
- [x] Табличные тесты адаптеров на фикстурах, включая кривые файлы.

### Сервисы Wails (`internal/app`)

Один сервис вместо трёх: у них общий индекс и жизненный цикл (сборка при запуске, наблюдение, закрытие). Ошибки — кодом (`item.not-found`, `library.failed`).

- [x] Событие Wails `index:updated` после каждой пересборки индекса.
- [x] Привязки TypeScript сгенерированы `wails3 task bindings` и лежат в `frontend/bindings`.

## Готово, когда

Приёмка на реальной памяти — вручную в `wails3 task dev REAL=true`, только чтение. Тест «не пишет за пределы каталога данных» — `TestRebuildDoesNotWrite` в `internal/library`.

Замер 2026-11-10 на памяти владельца (только чтение, индекс во временном каталоге, Linux), два профиля Claude (второй — через `extra_claude_profiles` в `config.toml`) и Codex v2: 238 записей в 36 проектах, пересборка 0,08 с, поиск по началу слова 9–10 мс, 5 проектов объединяют обоих агентов, 6 — несколько хранилищ. Приёмка владельцем 2026-11-10 в `wails3 task dev REAL=true`: в окне видна память Claude из обоих профилей.

- `wails3 dev` открывает окно, где на реальных данных владельца видна память обоих профилей Claude и Codex.
- Один и тот же проект, известный обоим агентам, показан одной строкой с обоими источниками.
- Поиск находит факт по началу слова из тела меньше чем за секунду на объёме машины владельца.
- Тестом доказано, что ни один код фазы не пишет за пределы каталога данных ai-memory (например, запуск на фикстурах в каталоге только для чтения).
