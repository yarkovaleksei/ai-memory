# Фаза 4. Инструкции и навыки

**Статус:** готова (2026-11-11)

**Цель.** Показывать и переносить между агентами не только автопамять, но и инструкции (`CLAUDE.md`, `AGENTS.md`) и навыки ([ADR-010](../decisions.md#adr-010-инструкции-и-навыки-агентов--тоже-в-охвате)).

## Задачи

### Исследование
- [x] Уточнить, какие файлы инструкций читает каждый агент и в каком порядке: глобальные, проектные, вложенные каталоги, `CLAUDE.local.md`, `.claude/CLAUDE.md`, `AGENTS.override.md`, импорты `@путь`. Итог — в [storage-formats.md](../storage-formats.md#инструкции-и-навыки).
- [x] Уточнить, где агенты ищут навыки (профиль, проект, плагины, общий `~/.agents/skills`) и какие поля frontmatter `SKILL.md` понимает каждый.

### Ядро
- [x] Виды записей: инструкции Claude и Codex (глобальные и проектные), навыки Claude и Codex ([architecture.md](../architecture.md#модель-данных)).
- [x] Адаптеры: глобальные инструкции из профилей; проектные — по путям проектов, уже известных из памяти; навыки — каталоги с `SKILL.md`.
- [x] Пути проектов для инструкций — и из каталогов проектов Claude без памяти: найдено на приёмке, у большинства проектов фактов нет ([ADR-025](../decisions.md#adr-025-пути-проектов-для-инструкций--и-из-каталогов-проектов-claude-без-памяти)).
- [x] Симлинки навыков: показывать цель, помечать навык как общий, если на одну цель ссылаются несколько агентов или профилей.
- [x] Разделы инструкций: нарезка по заголовкам, чтобы переносить не весь файл, а отдельное правило ([ADR-021](../decisions.md#adr-021-перенос-правила--раздел-по-заголовку-вставкой-в-другой-файл-инструкций)).
- [x] Перенос факта, объединение и «Забыть» отказывают инструкциям и навыкам и в Go, и в интерфейсе: у них будут свои операции.
- [x] Наблюдение за корнем профиля, `CODEX_HOME` и проектами — только по именам файлов инструкций, чтобы история и логи агентов не пересобирали индекс.
- [x] Writer: правка инструкций и навыков через план и diff; для файла внутри git-репозитория проекта — предупреждение в плане, для общего навыка — отдельное подтверждение ([ADR-020](../decisions.md#adr-020-как-пишутся-инструкции-и-навыки)).
- [x] Только чтение: системные навыки Codex, навыки из аккаунта claude.ai (`skills/synced`), навыки из памяти Codex (`memories*/skills`). Навыки плагинов в фазе 4 не читаются ([ADR-019](../decisions.md#adr-019-как-читаются-инструкции-и-навыки)).

### Перенос
- [x] Правило из `CLAUDE.md` в `AGENTS.md` и обратно — как вставка раздела с предпросмотром; отсутствующий файл агента создаётся, импорты `@` показываются в плане.
- [x] Предложение объединить инструкции проекта приёмом «`AGENTS.md` — основной, `CLAUDE.md` импортирует его через `@AGENTS.md`», как в этом репозитории ([ADR-022](../decisions.md#adr-022-приём-agentsmd--основной--блоки-claudemd-переносятся-в-claudemd-остаётся-импорт)).
- [x] Навык из одного агента в другой — копией или симлинком, с проверкой полей frontmatter, которые другой агент не понимает ([ADR-023](../decisions.md#adr-023-навык-ставится-в-другого-агента-копией-или-симлинком-через-writer)).
- [x] Поиск дублей и противоречий между инструкциями и автопамятью (например, правило есть и в `CLAUDE.md`, и фактом в памяти): инструкции отмечаются для проверки, модель различает противоречие и дубль ([ADR-024](../decisions.md#adr-024-инструкции-отмечаются-в-списке-только-для-проверки-противоречий-и-дублей-с-памятью)).

### Интерфейс
- [x] Разделы «Инструкции» и «Навыки» рядом с памятью в дереве проекта и в глобальной части: записи стоят в общем списке проекта, фильтр «Раздел» отделяет память, инструкции и навыки.
- [x] Бейджи: «общий навык», «только чтение», «файл в git-репозитории проекта»; у общего навыка — где ещё подключён его каталог.

### Приёмка
- [x] Ручная приёмка на реальной памяти — только с согласия владельца в чате: инструкции и навыки проекта видны рядом с памятью; правило переносится из `CLAUDE.md` в `AGENTS.md` и откатывается байт в байт; навык Claude ставится в Codex копией и симлинком, виден в навыках Codex и убирается откатом; дубль правила и факта находится проверкой.

Приёмка владельцем 2026-11-11 в `wails3 task dev REAL=true` (Linux). В `~/.claude*` и `~/.codex` по сценарию ничего не писали:
- Проект ai-memory: `CLAUDE.md` и `AGENTS.md` видны с чипом «В git-репозитории проекта». Подсказки «Сделать AGENTS.md основным» нет: `CLAUDE.md` уже импортирует `@AGENTS.md`.
- Раздел «Только для Claude Code» перенесён из `CLAUDE.md` в `AGENTS.md` одной операцией по двум файлам и откачен. Хэши обоих файлов совпали со снятыми до приёмки, `git status` репозитория чистый.
- Навык Claude `material-ui-styling` поставлен в `~/.agents/skills` копией (4 файла), виден в навыках Codex и откачен. Потом поставлен симлинком и тоже откачен. Список `~/.agents/skills` и хэши файлов исходного навыка совпали со снимком.
- «Найти противоречия» по глобальному `CLAUDE.md` и разделам сводки Codex отработала, находки помечены видом. «Объединить» неактивна, ничего не записано.
- В журнале бэкапов за приёмку — только эти операции и их откаты.
- Найдено и исправлено в ходе приёмки:
  - У 44 из 58 проектов Claude нет фактов автопамяти, и их инструкции не находились: пути проектов теперь берутся и из каталогов проектов Claude без памяти ([ADR-025](../decisions.md#adr-025-пути-проектов-для-инструкций--и-из-каталогов-проектов-claude-без-памяти)). Каталоги внутри профилей и `CODEX_HOME` проектами не считаются, повторы одного файла отбрасываются.
  - Индекс не собирался: консолидация Codex записала в `memory_summary.md` два раздела с одним заголовком, и ID совпали. Повтор заголовка теперь получает номер в якоре.
  - После отката копии навыка остаётся пустой каталог, и симлинк на его место не ставился. Теперь writer заменяет симлинком дерево пустых каталогов (каталог с файлами — нет), а зеркало бэкапа переносит смену каталога на файл и обратно.
  - В окне минимальной ширины кнопки «Создать» и «Перечитать» наезжали на поиск: теперь они переносятся под фильтры.

## Готово, когда
- Для проекта видны его инструкции обоих агентов и вся память по нему на одном экране.
- Правило переносится из `CLAUDE.md` в `AGENTS.md` с предпросмотром и откатывается.
- Навык Claude ставится в Codex копией или симлинком и после этого виден в навыках Codex.

## Риски
- Правка общего навыка через симлинк неожиданно меняет его у всех агентов. Смягчение: явный бейдж и отдельное подтверждение в плане.
- Проектные инструкции часто под git, и наши правки смешаются с работой владельца. Смягчение: предупреждение в плане и снимок в бэкапе; коммитить в чужой репозиторий ai-memory не будет никогда.
