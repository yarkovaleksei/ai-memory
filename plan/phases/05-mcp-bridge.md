# Фаза 5. MCP-мост

**Статус:** готова (2026-11-11)

**Цель.** Дать каждому агенту доступ к памяти другого прямо во время работы, без ручного переноса.

## Задачи
- [x] `cmd/ai-memory-mcp`: stdio MCP-сервер на `github.com/modelcontextprotocol/go-sdk` поверх ядра из `internal/`. Без зависимости от Wails и GTK. Инструменты — в `internal/bridge`, индекс — свой, в памяти процесса ([ADR-026](../decisions.md#adr-026-mcp-мост-свой-индекс-в-памяти-текущий-проект-память-другого-агента)).
- [x] Инструменты только на чтение: `search_memory(query, project?, agent?)`, `get_memory(id)`, `list_projects()`. Инструкции и навыки другого агента ([фаза 4](04-instructions-skills.md)) — тоже ищутся, с видом записи в выдаче. Добавлены аргументы `kind` и `limit`; по умолчанию поиск идёт по записям другого агента.
- [x] По умолчанию агент видит память другого агента по текущему проекту; глобальная — по флагу. Проект — по рабочему каталогу или `-project`; флаги `-global` и `-all-projects` у сервера, агент расширить видимость не может.
- [ ] Опционально и выключено по умолчанию: `propose_memory(...)` — создаёт черновик плана, который применяет человек в окне ai-memory. Агент сам ничего не пишет. **Отложено** ([ADR-026](../decisions.md#adr-026-mcp-мост-свой-индекс-в-памяти-текущий-проект-память-другого-агента)): черновик — запись на диск, а критерий фазы её запрещает; окну нужен приёмник черновиков.
- [x] Инструкция по подключению: `claude mcp add …` и раздел `[mcp_servers]` в `~/.codex/config.toml` — в README, раздел «MCP-мост».
- [x] Задача сборки бинаря MCP в `Taskfile.yml`: `build:mcp`; `mcp:dev` печатает команды, которые подключают мост к агентам на копии фикстур без записи в их настройки.
- [x] Тесты: протокольные тесты инструментов на фикстурах (`internal/bridge`: клиент go-sdk через транспорт в памяти; снимок фикстур и каталога данных до и после вызовов).

### Ручная приёмка
- [x] На копии фикстур (`wails3 task mcp:dev`): в Codex по проекту `demo` агент находит через MCP факт «Трекер задач», который есть только у Claude, а в Claude Code — rollout-сводку Codex о релизе. Проверить, в каком каталоге агенты запускают сервер и как называют себя в `initialize`.

Приёмка владельцем 2026-11-11 на копии фикстур (Linux):
- Claude Code на вопрос о релизе `demo` ответил по факту Claude `release-flow.md` и по rollout-сводке Codex о v1.2.0. Записи свёл и сравнил сам.
- Codex на вопрос о трекере вызвал `search_memory`, затем `get_memory` и ответил ссылкой из факта Claude `tracker-link.md`. Текущий проект нашёлся по рабочему каталогу: агенты запускают сервер в каталоге сессии.
- Найдено и исправлено: с первого раза Codex искал по файлам и мост не вызвал. Описание `search_memory` теперь говорит, когда искать в памяти раньше, чем в файлах: договорённости, история, ссылки проекта.
- Не проверено: имя клиента в `initialize`. В командах `mcp:dev` агент задан флагом `-agent`, и угадывание по имени не понадобилось.
- [ ] На реальной памяти, только с согласия владельца: подключение по README, поиск по одному проекту, время пересборки индекса. Не проводилась: владелец закрыл фазу по критериям готовности, которые проверяются на фикстурах.

## Готово, когда
- В сессии Codex по проекту из фикстуры агент находит через MCP факт, который есть только в памяти Claude, и наоборот.
- Ни один инструмент MCP не меняет файлы на диске.

## Риски
- Чужая память раздувает контекст. Смягчение: короткие выдачи (заголовок, описание, id), тело — только через `get_memory`.
- MCP-сервер и окно ai-memory одновременно строят индекс. Смягчение: общий файл индекса открывается в режиме WAL, MCP только читает его; если окна нет — строит свой в памяти. Уточнено [ADR-026](../decisions.md#adr-026-mcp-мост-свой-индекс-в-памяти-текущий-проект-память-другого-агента): мост всегда строит свой индекс в памяти и файл окна не открывает.
