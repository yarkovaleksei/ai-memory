# Журнал решений

Каждое решение — отдельная запись. Принятые записи не переписываются: если решение меняется, добавляется новая запись со ссылкой на старую, а у старой статус меняется на «заменено ADR-NNN».

Статусы: `предложено` — ждёт подтверждения владельца; `принято`; `заменено ADR-NNN`.

---

## ADR-001. Работать поверх родной памяти агентов, без своего хранилища

**Статус:** принято (2026-11-10)

**Контекст.** Готовые решения (claude-mem, codemem, Basic Memory, mem0/OpenMemory) добавляют третий, отдельный слой памяти через MCP или хуки. Родную автопамять Claude и Codex они не видят и не правят.

**Решение.** ai-memory читает и пишет родные файлы памяти агентов. Свои данные системы — только индекс, кэш и бэкапы, их можно удалить и пересобрать.

**Последствия.** Агентов не нужно перенастраивать. Зато мы зависим от недокументированных форматов и должны переживать их изменения.

---

## ADR-002. В память Codex писать только ad-hoc-заметками

**Статус:** принято (2026-11-10)

**Контекст.** `memory_summary.md`, `MEMORY.md` и `rollout_summaries/` Codex пересобирает при консолидации, прямые правки будут потеряны. `extensions/ad_hoc/notes/` — штатный канал, который Codex считает авторитетным. Удалять заметки запрещено его же инструкцией.

**Решение.** Все изменения памяти Codex — новые или изменённые ad-hoc-заметки. Удаление факта — заметка «забыть». Сгенерированные файлы — только чтение.

**Последствия.** Изменения в Codex применяются не сразу, а после консолидации. Интерфейс должен показывать это состояние («ожидает консолидации»).

## ADR-003. Стек: TypeScript на Node 24, Hono, React + react-admin + MUI

**Статус:** предложено

**Контекст.** Владелец — фронтенд-разработчик с опытом react-admin и MUI. Память — по сути CRUD над записями с фильтрами, это ровно задача react-admin. На машине есть Node 24 и npm; bun и cargo не установлены, pnpm через corepack сломан.

**Решение.**
- Монорепозиторий на npm workspaces: `packages/core`, `apps/server`, `apps/web`, позже `packages/mcp`.
- Сервер — Hono на `@hono/node-server`.
- Интерфейс — Vite + React + react-admin 5 + MUI, свой `dataProvider` поверх REST сервера.
- Редактор Markdown — CodeMirror 6, diff — `@codemirror/merge`.
- SQLite — `better-sqlite3` (FTS5 из коробки). Встроенный `node:sqlite` рассмотреть, когда стабилизируется.
- Тесты — Vitest; проверка типов — `tsc --noEmit`; линт — ESLint + Prettier.

**Последствия.** Один язык во всём проекте, адаптеры переиспользуются сервером и MCP-мостом.

## ADR-004. Сначала локальное веб-приложение, десктоп-оболочка — потом

**Статус:** предложено

**Контекст.** Tauri требует Rust, его на машине нет. Electron тяжёлый. Веб-интерфейс на localhost закрывает задачу «удобный GUI» сразу.

**Решение.** До фазы 5 — локальный сервер плюс страница в браузере. Вопрос упаковки (Tauri, Electron или PWA с автозапуском сервера) решается в [фазе 5](phases/05-packaging.md).

## ADR-005. LLM-операции через CLI агентов

**Статус:** предложено

**Контекст.** Объединение дублей и переформулирование требуют LLM. У владельца есть подписки на Claude и Codex, отдельных API-ключей заводить не хочется.

**Решение.** Вызывать `claude -p` и `codex exec` в неинтерактивном режиме с промптом и данными через stdin. Ответ — черновик, который проходит обычный путь записи с diff.

**Последствия.** Нужно следить, чтобы такие вызовы не создавали память сами о себе (у Codex — сессия попадёт в конвейер генерации). Проверить в [фазе 3](phases/03-cross-agent.md).
