# ai-memory

[Русская версия](README.md)

A desktop app for the memory of Claude Code and Codex: browse it by project, search it, edit and delete entries, move facts from one agent to the other, and merge duplicates.

> **Status:** phases 1 (browsing), 2 (editing), 3 (cross-agent) and 4 (instructions and skills) are done; next is phase 5, the MCP bridge. The window shows Claude Code and Codex memory by project, with search; Claude facts can be edited, created and deleted, and Codex gets notes. Records move between agents, and the ones checked in the list can be merged and checked for contradictions, optionally with a draft from the model. Instructions (`CLAUDE.md`, `AGENTS.md`, rules) and skills sit next to the memory: a rule moves between `CLAUDE.md` and `AGENTS.md` as a section, and a skill is installed into the other agent as a copy or a symlink. Every write goes through a diff, a backup and a history with undo; writing needs `git`. Work follows the [plan](plan/README.md). How to run and check it: the commands section of [AGENTS.md](AGENTS.md). The plan and the developer docs are written in Russian.

## Why

If you switch between Claude Code and Codex, each of them builds up its own memory and neither can see the other's. A conclusion reached in one agent has to be repeated in the other. Seeing what an agent "remembers" about you, and cleaning it up, means editing files by hand in two different formats.

Existing tools (claude-mem, codemem, Basic Memory, mem0/OpenMemory) solve a different problem: they add a separate, shared memory layer over MCP. They don't show or edit the agents' own built-in memory.

## How it works

ai-memory keeps no memory of its own. It works on top of the agents' native files:

| Agent | Where memory lives | How ai-memory writes |
|---|---|---|
| Claude Code | `~/.claude*/projects/<project>/memory/*.md` plus the `MEMORY.md` index | directly: the fact file and its index line |
| Codex | `~/.codex/memories_v2/` (summary and rollout summaries, generated by Codex itself) | only through ad-hoc notes in `extensions/ad_hoc/notes/`, which Codex merges into its memory on consolidation |

Every write is previewed as a diff and saved to a separate backup repository, so any operation can be undone.

## Settings

With no settings, ai-memory reads the Claude Code profile `~/.claude` (plus the directory in `CLAUDE_CONFIG_DIR`, if set) and Codex from `~/.codex` (or `CODEX_HOME`). If you keep several Claude profiles, say a work one and a personal one in different directories, add them on the Settings screen: you pick the directory in the system dialog and memory is reread at once. The screen writes `config.toml` in the settings directory (`~/.config/ai-memory/` on Linux, `~/Library/Application Support/ai-memory/` on macOS, `%AppData%\ai-memory\` on Windows), which you can also edit by hand:

```toml
# Extra Claude Code profiles. Any names; ~ expands to your home directory.
extra_claude_profiles = ["~/.claude-work", "~/.claude-personal"]

# Codex root, if it is not ~/.codex and CODEX_HOME is not set.
# codex_home = "/opt/codex"

# The Codex memory generation it currently writes to: "v1" (memories/) or "v2" (memories_v2/).
# Usually not needed: ai-memory detects it from Codex's settings and databases.
# codex_generation = "v2"

# Also show the inactive generation (read-only: Codex no longer reads it).
# show_codex_inactive = true
```

A directory listed twice, including through a symlink, is read once. Settings are read at startup; restart the app after editing them.

## Planned features

1. **Browse (MVP).** Memory of both agents by project, filters, full-text search. Read-only.
2. **Edit.** Create, change and delete with a diff preview, backup and undo.
3. **Across agents.** Move facts between Claude and Codex; merge the entries you select and look for contradictions among them (the draft and the check use an LLM through `claude -p` / `codex exec`).
4. **Instructions and skills.** `CLAUDE.md`, `AGENTS.md` and skills next to memory; move rules and skills between agents.
5. **MCP bridge.** An agent can search the other agent's memory while it works.
6. **Packaging.** Installers for Linux, macOS and Windows.

## Stack

Go and Wails v3 for the core and the window; React, TypeScript, react-admin 5, MUI and CodeMirror 6 for the UI, with yarn 4; SQLite FTS5 for the index. The UI is in Russian first, with i18n from day one. Targets Linux, macOS and Windows. Details: [ADR-006](plan/decisions.md#adr-006-стек-go--wails-v3-react-admin-yarn-4).

## Privacy

- The app opens no network port; memory never leaves your machine.
- ai-memory keeps its own data (index and backups) in the user data directory: `~/.local/share/ai-memory/` on Linux, `~/Library/Application Support/ai-memory/` on macOS, `%LocalAppData%\ai-memory\` on Windows. It can be deleted at any time and is rebuilt from the agents' files.
- Tests run on fixtures only; no real memory ever goes into the repository.
