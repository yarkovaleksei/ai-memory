# ai-memory

[Русская версия](README.md)

A desktop app for the memory of Claude Code and Codex: memory, instructions and skills of both agents on one screen, editing with undo, and moving things from one agent to the other.

> **Status:** phases 1–5 are done. Phase 6, packaging, is in progress: packages for all three systems build, but so far they are tested on Linux only. Work follows the [plan](plan/README.md); how to run and check it: the commands section of [AGENTS.md](AGENTS.md). The plan and the developer docs are written in Russian.

## What it does

- Shows Claude Code and Codex memory by project, with filters and full-text search.
- Edits, creates and deletes Claude facts; for Codex it writes notes that Codex merges into its memory itself.
- Moves records between agents, merges the duplicates you select and looks for contradictions among them, optionally with a draft from the model.
- Shows instructions (`CLAUDE.md`, `AGENTS.md`, rules) and skills next to the memory: moves a rule between `CLAUDE.md` and `AGENTS.md` as a section, installs a skill into the other agent as a copy or a symlink.
- Through the `ai-memory-mcp` bridge, an agent searches the other agent's memory while it works.
- Every write goes through a diff, a backup and a history with undo; writing needs `git`.

## Why

If you switch between Claude Code and Codex, each of them builds up its own memory and neither can see the other's. A conclusion reached in one agent has to be repeated in the other. Seeing what an agent "remembers" about you, and cleaning it up, means editing files by hand in two different formats.

Existing tools (claude-mem, codemem, Basic Memory, mem0/OpenMemory) solve a different problem: they add a separate, shared memory layer over MCP. They don't show or edit the agents' own built-in memory.

## How it works

ai-memory keeps no memory of its own. It works on top of the agents' native files:

| Agent | Where memory lives | How ai-memory writes |
|---|---|---|
| Claude Code | `~/.claude*/projects/<project>/memory/*.md` plus the `MEMORY.md` index | directly: the fact file and its index line |
| Codex | `~/.codex/memories_v2/` (summary and rollout summaries, generated by Codex itself) | only through ad-hoc notes in `extensions/ad_hoc/notes/`, which Codex merges into its memory on consolidation |

Every write is previewed as a diff and saved to a separate backup repository, so any operation can be undone.

## Settings

With no settings, ai-memory reads the Claude Code profile `~/.claude` (plus the directory in `CLAUDE_CONFIG_DIR`, if set) and Codex from `~/.codex` (or `CODEX_HOME`). If you keep several Claude profiles, say a work one and a personal one in different directories, add them on the Settings screen: you pick the directory in the system dialog and memory is reread at once. The screen writes `config.toml` in the settings directory (`~/.config/ai-memory/` on Linux, `~/Library/Application Support/ai-memory/` on macOS, `%AppData%\ai-memory\` on Windows), which you can also edit by hand:

```toml
# Extra Claude Code profiles. Any names; ~ expands to your home directory.
extra_claude_profiles = ["~/.claude-work", "~/.claude-personal"]

# Codex root, if it is not ~/.codex and CODEX_HOME is not set.
# codex_home = "/opt/codex"

# The Codex memory generation it currently writes to: "v1" (memories/) or "v2" (memories_v2/).
# Usually not needed: ai-memory detects it from Codex's settings and databases.
# codex_generation = "v2"

# Also show the inactive generation (read-only: Codex no longer reads it).
# show_codex_inactive = true
```

A directory listed twice, including through a symlink, is read once. Settings are read at startup; restart the app after editing them.

## Installation

Packages are in the [GitHub releases](https://github.com/yarkovaleksei/ai-memory/releases); checksums are in `SHA256SUMS-<system>.txt`. The MCP bridge `ai-memory-mcp` is installed with the window. The packages are not signed ([ADR-027](plan/decisions.md#adr-027-упаковка-без-подписи-deb-rpm-arch-dmg-и-nsis-с-mcp-мостом)), so macOS and Windows ask for confirmation on first launch. How to give it is below.

| System | Package | Window | MCP bridge |
|---|---|---|---|
| Ubuntu 24.04+, Debian 13+ | `ai-memory_X.Y.Z_amd64.deb` | application menu, `ai-memory` | `/usr/bin/ai-memory-mcp` |
| Fedora 40+ | `ai-memory-X.Y.Z.x86_64.rpm` | application menu, `ai-memory` | `/usr/bin/ai-memory-mcp` |
| Arch Linux | `ai-memory-X.Y.Z-x86_64.pkg.tar.zst` | application menu, `ai-memory` | `/usr/bin/ai-memory-mcp` |
| macOS 12+, Apple Silicon and Intel | `ai-memory-X.Y.Z-macos-universal.dmg` | Applications → ai-memory | `/Applications/ai-memory.app/Contents/MacOS/ai-memory-mcp` |
| Windows 10 and 11, x64 | `ai-memory-X.Y.Z-windows-amd64-setup.exe` | Start menu and a desktop shortcut | `%LOCALAPPDATA%\Programs\ai-memory\ai-memory-mcp.exe` |

**Linux.** Install with the usual package manager; it pulls in GTK 4 and WebKitGTK 6.0. On Ubuntu the deb also installs the AppArmor profile `/etc/apparmor.d/ai-memory`: without it the WebKit sandbox cannot start and the window does not open from the menu ([ADR-028](plan/decisions.md#adr-028-deb-ставит-профиль-apparmor-с-правилом-userns)).

```bash
sudo apt install ./ai-memory_X.Y.Z_amd64.deb
```

```bash
sudo dnf install ./ai-memory-X.Y.Z.x86_64.rpm
```

```bash
sudo pacman -U ./ai-memory-X.Y.Z-x86_64.pkg.tar.zst
```

**macOS.** Open the `.dmg` and drag ai-memory to Applications. The app is not notarized, so on first launch macOS says it cannot verify the developer. There are two ways to allow it:
- open System Settings → Privacy & Security and click "Open Anyway" next to the message about ai-memory;
- or remove the quarantine flag in a terminal. The command also clears it from the MCP bridge inside the app:

```bash
xattr -dr com.apple.quarantine /Applications/ai-memory.app
```

**Windows.** Run the installer. SmartScreen shows "Windows protected your PC": click "More info", then "Run anyway". The installer puts ai-memory in `%LOCALAPPDATA%\Programs\ai-memory` for the current user and needs no administrator rights. If WebView2 is missing, the installer downloads it.

**Updating** means installing the new package over the old one. The index, backups and settings live in the user's data and settings directories (see Privacy), and packages never touch them. They also stay after uninstalling; delete them by hand if you no longer need them.

**From source:** `wails3 task package` builds the packages for the current system into `bin/`. Requirements: the commands section of [AGENTS.md](AGENTS.md). Release packages for Linux are built locally; macOS and Windows packages are built by GitHub Actions on a tag ([ADR-029](plan/decisions.md#adr-029-linux-собирается-локально-macos-и-windows--в-ci)).

Tested on Linux only. The macOS and Windows packages are built in CI but have not been run on those systems yet. Where agent memory lives there is not verified either ([Q10](plan/open-questions.md)).

## MCP bridge

`ai-memory-mcp` is a separate binary with no window, Wails or GTK. The agent itself runs it as a stdio MCP server, and while it works it can find what the other agent knows about the project. The tools only read:

| Tool | What it does |
|---|---|
| `list_projects` | visible projects and the current one |
| `search_memory(query?, project?, agent?, kind?, limit?)` | short results: id, title, description, snippet, record kind (`memory`, `instructions`, `skill`). By default, the other agent's records for the current project |
| `get_memory(id)` | the whole record |

The bridge writes nothing: neither to agent memory nor to the ai-memory data directory. It keeps its index in process memory and re-reads the files at most every 10 seconds. Memory roots are the same as the window's: environment variables and `config.toml`.

The bridge is installed with the app; its path on each system is in the table under Installation. From source, `wails3 task build:mcp` builds it into `bin/`. Connect it for all projects (the example uses the Linux path):

```bash
claude mcp add --scope user ai-memory -- /usr/bin/ai-memory-mcp -agent claude
```

In Codex, run `codex mcp add ai-memory -- /usr/bin/ai-memory-mcp -agent codex` or add a section to `~/.codex/config.toml`:

```toml
[mcp_servers.ai-memory]
command = "/usr/bin/ai-memory-mcp"
args = ["-agent", "codex"]
```

Server flags:

| Flag | Effect |
|---|---|
| `-agent claude\|codex` | who connects: search defaults to the other agent's memory. Without it, guessed from the client name |
| `-project <dir>` | project directory. Default: the working directory the agent started the server in |
| `-global` | also show global memory: shared facts, global `CLAUDE.md` and `AGENTS.md`, user skills |
| `-all-projects` | show every project, not only the current one; search accepts `project: "all"` |
| `-refresh 10s` | how often to re-read memory |

Visibility is set by flags only: the agent cannot widen it through tool arguments. The decision and its reasons: [ADR-026](plan/decisions.md#adr-026-mcp-мост-свой-индекс-в-памяти-текущий-проект-память-другого-агента) (in Russian).

## Planned features

1. **Browse (MVP).** Memory of both agents by project, filters, full-text search. Read-only.
2. **Edit.** Create, change and delete with a diff preview, backup and undo.
3. **Across agents.** Move facts between Claude and Codex; merge the entries you select and look for contradictions among them (the draft and the check use an LLM through `claude -p` / `codex exec`).
4. **Instructions and skills.** `CLAUDE.md`, `AGENTS.md` and skills next to memory; move rules and skills between agents.
5. **MCP bridge.** An agent can search the other agent's memory while it works.
6. **Packaging.** Installers for Linux, macOS and Windows.

## Stack

Go and Wails v3 for the core and the window; React, TypeScript, react-admin 5, MUI and CodeMirror 6 for the UI, with yarn 4; SQLite FTS5 for the index. The UI is in Russian first, with i18n from day one. Targets Linux, macOS and Windows. Details: [ADR-006](plan/decisions.md#adr-006-стек-go--wails-v3-react-admin-yarn-4).

## Privacy

- The app opens no network port; memory never leaves your machine.
- ai-memory keeps its own data (index and backups) in the user data directory: `~/.local/share/ai-memory/` on Linux, `~/Library/Application Support/ai-memory/` on macOS, `%LocalAppData%\ai-memory\` on Windows. It can be deleted at any time and is rebuilt from the agents' files.
- Tests run on fixtures only; no real memory ever goes into the repository.
